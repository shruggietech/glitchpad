# S046 Android document recovery and standalone authoring

## Added

- Android Add document exposes New Markdown, New text file and native Open; local drafts and explicit editable copies gain provider identity only after verified destination creation.
- Native diagnostic Save verifies the frozen JSON bytes by readback, while Share uses temporary receiver access and reports system handoff separately from recipient delivery.
- Diagnostic failures carry bounded allowlisted component/stage/reason/correlation context and actual Android/WebView/build facts where available.

## Fixed

- Markdown worker, response, asynchronous projection and document failures terminate visibly; plain bootstrap and application-root recovery remain available outside document rendering.
- Shared menu/keyboard/renderer actions report actual results, await clipboard operations, route Save through native outcomes and share image/diagram Zoom/Fit state.
- Android destination writes reject source aliases and conflicting/nonempty destinations before destructive access; cancellation, failed writes, newer edits and pending Close/Discard retain their correct state.
- Lifecycle recovery snapshots flush before controlled restart and preserve source-independent Markdown/text state.

## Decisions

- 2026-11-03: Use the existing bounded recovery store and Kotlin create/write/sync/readback path through separate source-independent and source-bound contracts; do not fabricate provider grants or implement unsupported in-place durability.
- 2026-11-04: Extend hosted qualification to retain the exact installed/tested APK, real product/source/runtime identity and every attempt log. Debug/source-equivalent evidence remains distinct from signed release-byte evidence.

- 2026-11-04: Add the pinned brand verifier renderer/PDF prerequisites to the reusable validation image; generated audit output is isolated from shipped kit bytes.
