# Unreleased PDF candidate

S049 adds the candidate PDF viewer described by [the slice specification](../../specs/049-pdf-viewer-foundation/spec.md). Version 0.2.1 remains the published release. PDF file associations, Android PDF intents and public stable support remain separate activation work.

Open a local PDF through the existing file picker or an explicitly granted delivery. The document stays read only. The PDF controls provide previous/next page, a page-number task and fit. More PDF tools contains zoom (10–800 percent), rotation, continuous/single-page layout, search, outline, thumbnails, page links, printing and file information. Stored page labels appear in page semantics and file information; page-number entry always uses the physical one-based page ordinal.

Search produces ordered page results with context. Selecting a result navigates to its page and selects matching visible text. Search is cancellable and bounded to 2,000 results and 1,000,000 extracted characters per page. Outline inspection is bounded to 4,096 entries and depth 32. Thumbnails load in batches of at most eight and pause in reduced-cache mode. Page links disclose external destinations before an explicit operating-system opener request. Unsupported schemes and document actions do not launch.

Desktop sources are limited to 512 MiB, Android sources to 256 MiB and documents to 10,000 pages. Stream-only Android sources use one bounded private disk cache with progress and cancellation. Visible pages and a bounded adjacent window render on demand; individual/aggregate canvas budgets are 200 MiB on desktop and 96 MiB on Android. Excessive surface or host scroll geometry produces reduced-cache/single-page behavior or a concrete refusal with a smaller-zoom remedy. Background/switch/close stops the actual worker and page work; compact navigation remains session-only.

Print all pages or a comma-separated selection such as 1-3, 5. Printing prepares a source-bound raster snapshot. Android validates private PNG pages and uses the system print adapter, decoding one requested page at a time. Desktop requests its native print dialog. A dialog request, written system spool and adapter finish are distinct outcomes; none confirms paper output. Print staging is limited to 128 MiB encoded, 16 MiB per page and 16 million pixels per Android page; the desktop snapshot also has a 200 MiB aggregate decoded budget. Choose a smaller range when a print budget is exceeded. Source bytes are never replaced by print output.

PDF file information contributes version/pages/labels, encryption and stored permission flags, document information fields, current-page dimensions, outline and unsupported-feature facts through the existing provenance/availability catalog. Missing fields remain Not provided. Stored permission flags are informational. Embedded fonts and platform font fallback are used; unembedded font appearance can vary. Embedded ICC profiles are not applied. PDF scripts, form submission/editing, attachment launch, embedded media and automatic remote resources are not activated.

Current qualification, failed diagnostics and exact source/artifact identities are maintained in [the S049 validation ledger](../../specs/049-pdf-viewer-foundation/validation.md). Candidate behavior is not release qualification.
