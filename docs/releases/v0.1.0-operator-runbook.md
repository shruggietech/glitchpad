# v0.1.0 Release Operator Runbook

## Stable Android authority

Generate one long-lived RSA 3072-bit Android keystore with `keytool`, store it and its recovery material in the owner’s secure password manager, and record the certificate SHA-256 fingerprint. Never add the keystore, passwords, alias, or private paths to the repository.

Configure the repository secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, and `ANDROID_SIGNING_CERT_SHA256`. The base64 value must encode the keystore bytes without line wrapping. The fingerprint must be the uppercase colon-separated SHA-256 certificate fingerprint reported by `keytool -list -v`.

## Publication ritual

1. Confirm the S026 pull request is merged, all required checks are green, and the local checkout matches current `main`.
2. Confirm the stable Android keystore recovery copy is accessible outside the repository.
3. Manually dispatch the `release` workflow from current `main` and require `Validate release preparation` to pass. This verifies all five Android secrets without printing their values and cannot publish.
4. Confirm no local tag, remote tag, or GitHub release named `v0.1.0` already exists.
5. Create the annotated tag `v0.1.0` on the reviewed S026 merge commit and push only that tag.
6. Watch the four package workflows and the release workflow. Any missing platform artifact, failed check, or Android fingerprint mismatch must stop publication.
7. Confirm the GitHub release contains the eight declared packages, four evidence bundles, `SHA256SUMS`, and `community-release-manifest.json`.

The release workflow refuses to replace an existing v0.1.0 release. Manual workflow dispatch validates committed evidence and Android release-authority availability only; it cannot publish.
