# v0.1.2 Release Operator Runbook

## Stable Android authority

Reuse the v0.1.0 and v0.1.1 RSA 3072-bit Android keystore and its existing recovery material. Do not generate a replacement key. Confirm that the repository secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, and `ANDROID_SIGNING_CERT_SHA256` remain configured without printing their contents. The expected fingerprint is the existing uppercase colon-separated SHA-256 certificate fingerprint.

## Publication ritual

1. Confirm the S032 pull request is merged, all required checks are green, and the local checkout matches current `main` at the reviewed merge commit.
2. Confirm the stable Android keystore recovery copy is accessible outside the repository.
3. Manually dispatch the `release` workflow from current `main` and require `Validate release preparation` to pass. This verifies committed evidence and all five Android authority values without printing them and cannot publish.
4. Confirm no local tag, remote tag, or GitHub release named `v0.1.2` already exists.
5. Create the annotated tag `v0.1.2` on the reviewed S032 merge commit and push only that tag.
6. Watch the Windows, macOS, Linux, Android, and release workflows. Any missing package, failed gate, stale identity, or Android fingerprint mismatch must stop publication.
7. Confirm the GitHub release contains exactly eight application packages, four evidence bundles, `SHA256SUMS`, and `community-release-manifest.json`.
8. Confirm every package and evidence record names v0.1.2 and the reviewed source revision, then record publication against issue #157.

The release workflow refuses to replace an existing v0.1.2 release. Manual workflow dispatch validates readiness only; publication remains restricted to the exact post-merge `v0.1.2` tag.
