# Glitchpad v0.1.2 Corrective Release

Glitchpad v0.1.2 is the second corrective release following v0.1.0. It combines the public presentation and brand corrections from S029, the Markdown and compact-shell corrections from S030, and the Android system file-opening corrections from S031 without broadening the stable format matrix.

## What changed

- Repository and website branding now use the current Glitchpad brand authority, legible lockups, ShruggieTech attribution, the approved slogan, compact actions, current release claims, and release-consistent specification dates and versions.

- A document-scoped failure boundary keeps the application shell available and offers explicit source recovery for Markdown.
- Markdown render results are accepted only for the current session, revision, and render generation.
- Rendered mode shows a constant pending state without exposing source-derived content.
- The application menu trigger remains fixed at the upper-left and its popup does not participate in document layout.
- The README retains its supported-platform table while dropping the oversized Platforms badge.
- Packaged Windows validation exercises two complex Markdown documents in both open orders and records active-content evidence.
- Android exact-type file opening no longer depends on a filename or extension appearing in an opaque provider URI.
- Android package evidence retains complete intent-filter groups so invalid merged matcher semantics cannot pass as a flat inventory.
- Android cold-start and warm intents now drain through a permission-scoped native event into the bounded document gateway, so accepted provider content reaches the viewport and native source authority is released when the session closes.
- Installed-package checks on API 24 and API 36 prove resolver eligibility plus cold and warm document delivery through scoped provider grants.
- Providers that report only a generic binary media type for an opaque URI cannot be identified safely at resolver time. Glitchpad intentionally declines that ambiguous case instead of claiming every binary document; opening through the in-app picker remains available.
- Android callers can supply broad request types such as `text/*`, `application/*`, or `*/*`; Android matches those requests to Glitchpad's exact declarations. Glitchpad does not declare wildcard types and still applies its normal content detection after delivery.

## Packages and platforms

The official release contains eight application packages: an unsigned Windows NSIS installer and portable ZIP, a universal macOS DMG with an ad-hoc signature that is not notarized, Linux AppImage and Debian packages with repository attestations, and Android universal APK, ARM64 APK, and AAB packages signed by the stable project-owned update key. Windows SmartScreen and macOS Gatekeeper may warn because this zero-cost community release does not use paid platform trust programs.

Each package is accompanied by SHA-256 checksums, software-bill-of-materials data, provenance, license notices, the reviewed source revision, and machine-readable trust evidence.

## Supported capabilities and limits

Glitchpad v0.1.2 supports local Markdown, Mermaid, plain-text, and recognized source files with the released view, edit, save, search, inspection, recovery, and compact multi-document behaviors. Image, PDF, DOCX, and ODT support remains planned for later releases and is not included here. The application has no account, telemetry, or file-content network dependency. Remote document resources remain blocked.

## Installation and feedback

Download packages only from the official GitHub release, verify `SHA256SUMS`, and review the platform trust evidence before installation. Report defects through the repository issue tracker. Manual real-world validation remains post-release work tracked by issue #66.
