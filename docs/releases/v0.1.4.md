# Glitchpad v0.1.4 Brand and Shell Release

Glitchpad v0.1.4 packages the completed BrandBuilder 2.0.3 integration and AppFrame layout work on all four supported platforms. It follows the v0.1.3 corrective release and keeps the stable text-family support matrix.

## What changed

- The application shell uses the governed BrandBuilder AppFrame for safe areas, display cutouts, orientation, text scaling, menu geometry, and on-screen-keyboard insets.
- The formal Glitchpad brand 1.1.1 kit refreshes Android launcher artwork and supplies separate ordinary and maskable web icons. The approved square identity and existing Windows and macOS icon binaries remain consistent with that kit.
- The public site and package assets use the pinned kit with exact-copy and conformance checks.
- Compatible npm, Cargo, and Gradle wrapper updates are included after their platform checks pass.
- The already merged S039 and S040 image preview, inspection, animation, and selected ICO export code is present in the application. Image formats remain outside the stable support matrix and operating-system associations until the v0.2.0 conformance and activation work in #75 and #76 is complete.

## Packages and trust states

The release contains eight application packages: an unsigned Windows NSIS installer and portable ZIP, a universal macOS DMG with an ad-hoc signature that is not notarized, Linux AppImage and Debian packages with repository attestations, and Android universal APK, ARM64 APK, and AAB packages signed by the existing project-owned update key. Windows SmartScreen and macOS Gatekeeper may warn because this community release does not use paid platform trust programs.

Each package has SHA-256 checksums, software-bill-of-materials data, provenance, license notices, the source revision, and machine-readable trust evidence. Desktop evidence bundles bind practical-use receipts to final package manifests. The Android matrix retains API 24 and API 36 provider-backed delivery checks.

## Supported capabilities and limits

The stable support claim remains local Markdown, Mermaid, plain-text, and recognized source files with view, edit, save, search, inspection, recovery, and compact multi-document behaviors. Image implementations are included for in-app use but are not declared stable or associated with operating-system file openers in this release. PDF, DOCX, and ODT remain planned. The application has no account, telemetry, or file-content network dependency, and remote document resources remain blocked.

## Installation and feedback

Download packages from the official GitHub release, verify `SHA256SUMS` for SHA-256 integrity, and review the platform trust evidence before installation. Report defects through the repository issue tracker. Manual real-world validation remains post-release work tracked by issue #66.
