# Glitchpad v0.2.1 operator runbook

S048 prepares S046 and S047 product recovery for #244 and #255. Stop unmerged with auto-merge disabled. Tagging and publication require later owner authorization. This session must not execute the publication sequence below.

## Preparation and owner review

1. Reconcile the target product/specification version 0.2.1 and pinned package/brand contracts. Current source describes confirmed behavior and actual limits; immutable prior receipts stay unchanged.
2. Complete focused tests, exact branch-source checks, four ordinary/fault-probe Android campaigns, separately scoped actual minified release-runtime tests and affected native/platform package gates. Preserve every attempt and explicit unrun/waived row.
3. Stage final community/stable-project trust metadata before native receipt capture. Select exact source/run/attempt/artifact creation identities, independently verify all eight payload digests and retain actual installed APK/readback evidence. Preserve the distinction between eligible signing and publication.
4. Complete Spec-Kit convergence, resolve findings within two external rounds and hand the unmerged PR to the owner. The final PR confirmation and retained accepted staging input identify the current accepted candidate; #244/#255 remain open.

## Later separately authorized publication

1. Obtain the owner's publication authorization after final review and merge. Verify merged main contains the accepted candidate's exact tree. Preserve the accepted candidate SHA in package/About/provenance identities; do not rename it to a different squash-merge SHA.
2. Read the reviewed accepted staging inputs from the final handoff. They identify version/tag, accepted candidate SHA, four platform run IDs, exact immutable artifact sets/archive hashes and eight accepted payload digests. Validate every identity and require all current gates; retain failures rather than selecting an older pass.
3. Create the annotated v0.2.1 tag at the accepted candidate SHA, using the validated accepted staging input record as the tag annotation, and push only that tag through the approved hidden VCS/isolated operator path. A different source or package requires new qualification and acceptance.
4. The publisher must consume accepted payloads without rebuilding. It downloads the exact selected artifact IDs, verifies source/trust/archive/payload/native-receipt bindings and runs the strict complete release assembler. It refuses existing-release replacement and partial publication.
5. Independently read the resulting tag object, every public asset/manifest/checksum/provenance and release destination. The authorized site deployment must identify the same published tag/source; independently read it back. Public download links must resolve to that actual release.
6. Record the final publication/readback receipt, move project Stage through Release verification and close #255/#244 only when all criteria are satisfied. Keep issue #66 and #239 separate unless their own evidence and disposition are completed.

## Accepted input record and later tag

The accepted staging inputs format is defined in [the S048 contract](../../specs/048-v021-recovery-release/contracts/accepted-staging-inputs.md). The final PR confirmation provides its populated JSON artifact after exact-source qualification. Review the entire record, including run attempts, archive digests, payload hashes and manual/physical limits, before granting later owner authorization.

After the owner merges the PR, compare the main tree with the accepted candidate SHA. A squash merge may have a different commit SHA with the same tree. Keep the compiled and installed accepted source identity; do not substitute the squash merge SHA in provenance or About. The publisher requires the accepted tree to match main.

Only after that review and later owner authorization, the operator may create an annotated tag whose entire message is the accepted JSON file:

```powershell
$accepted = (Get-Content -Raw -LiteralPath .\accepted-staging.json | ConvertFrom-Json).accepted_source_commit
.\scripts\invoke-vcs-hidden.ps1 git tag -a v0.2.1 $accepted -F .\accepted-staging.json
.\scripts\invoke-vcs-hidden.ps1 git push origin refs/tags/v0.2.1
```

These are future operator instructions. No tag or publication is executed by S048 autopilot. Manual release workflow dispatch remains a non-publishing readiness check from main. Project-key material stays in Android preparation; final publication uses the configured public certificate fingerprint to verify accepted installed bytes.
