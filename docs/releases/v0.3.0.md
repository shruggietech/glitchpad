# Glitchpad v0.3.0

S050 prepares the S049 PDF viewer and its conformance/stable-activation gate for #81, #82 and epic #11. This source defines the release; publication and exact accepted source/package identities remain separate in the [preparation receipt](v0.3.0-receipt.md).

## PDF viewing

Open PDF files through the file picker, desktop associations, or exact Android Open/Share delivery. The custom PDF.js 6.5.438 worker viewer provides selectable text, ordered search, thumbnails, outline/named destinations, page labels, page entry, fit/zoom/rotation, internal links, external-link disclosure, metadata and system printing. Source documents remain read only and original bytes are preserved.

PDF JavaScript, form submission, attachment launch, automatic remote resources, embedded media and document modification remain disabled. DOCX and ODT are planned. Advanced PDF editing, annotations, signatures and other #227-#237 tools belong to a later release.

Print all pages or an explicit range. Desktop opens the native system print dialog; Android uses its system print adapter and can retain actual selected/all PDF output. A dialog, generated spool and adapter completion are distinct observations; none confirms physical paper output.

## Fidelity and resource limits

Embedded fonts and platform fallback preserve readable text where available; unembedded font appearance may vary. Embedded ICC color profiles are not applied. Original JPX/JBIG2 fixtures exercise the static decoder paths, and an OFL-licensed Hebrew CID/ToUnicode fixture checks logical text, selection and RTL direction. Hebrew coverage does not claim Arabic shaping.

Desktop sources are bounded to 512 MiB, Android sources to 256 MiB, and documents to 10,000 pages. Owned rendered surfaces are bounded to 200 MiB desktop or 96 MiB Android; source-range reads and concurrency remain bounded. Reduced cache, suspension, cancellation and explicit refusals retain the available source. First-page/navigation/search/thumbnail, named-process RSS/PSS and cache observations retain their methods and raw samples. Process totals do not establish parser-worker heap bounds.
