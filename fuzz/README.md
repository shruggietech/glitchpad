# Bounded core/image fuzz qualification

This development-only cargo-fuzz target calls the application's image detector, metadata parser, ICO inventory and family decoder. It asserts metadata-count, generated-PNG, decoded-surface and source-save capability invariants under a 64 KiB input ceiling and deliberately smaller harness allocation limits. Those limits do not redefine product support. Existing host source/export tests cover destination identity, cancellation and write integrity.

Use the `qualification` stage of `scripts/docker/validation.Dockerfile`, which pins cargo-fuzz 0.13.2 and nightly-2026-10-31. Cargo-fuzz requires a nightly toolchain and C++ compiler ([upstream setup](https://rust-fuzz.github.io/book/cargo-fuzz/setup.html)). `fuzz/Cargo.lock` locks the independent development-only graph; no fuzz dependency ships in application packages.

Copy the original corpus into a disposable `.tmp/s043-fuzz/corpus` directory before running so libFuzzer never mutates the authoritative fixture directory. Run `cargo +nightly-2026-10-31 fuzz run image_boundaries .tmp/s043-fuzz/corpus -- -max_total_time=60 -timeout=10 -rss_limit_mb=1536 -max_len=65536 -seed=43 -artifact_prefix=.tmp/s043-fuzz/`. Retain the console output, resulting corpus and crashes. A nonzero exit or any timeout/OOM/crash is a failed campaign, not a passing classified refusal. Minimize failures and promote the reproducer with a focused native regression before retrying.

The libFuzzer entry point delegates to `src/lib.rs`, which always exercises uncancelled frame/entry zero before an independent arbitrary selector and then checks cancellation separately. `cargo test --manifest-path fuzz/Cargo.toml --lib --locked` requires original JPEG, GIF, animated WebP, SVG and ICO seeds to reach pixel output. The seed regression failed against the signature-derived cancellation rule before correction.
