The canonical minified universal APK from the staged Android package is installed unchanged on API24/API36. Its existing project certificate is verified during staging, and installed bytes are captured and independently hashed against the accepted payload. The production target is not debuggable; instrumentation is a separate matching-signature, test-only/debuggable APK. The Gradle release test variant is opt-in, with default debug unchanged.

Reuse cold/warm provider delivery/images/ICO-export, standalone New/Open/edit/save/reopen/copy/cancel/pending/Diagnostics and separate seed/verify exact recovery. Release-runtime coverage is named separately from existing full ordinary/fault-probe debug matrices. The latter retain every required ten-journey/profile assertion. No supplemental or conditional debug row is relabelled as an individual installed-release pass.

Use bounded ADB exec-out streams and run-as only on the debuggable test package; independently validate JSON, screenshot digests and canonical installed APK hashes before acceptance. Capture before provider reset; keep evidence out of authoring document cleanup. Preserve two process attempts, current per-action deadlines, clean-positive JUnit/markers/adb/crash checks, failed captures and destination/receiver readbacks.

## Test-runtime ABI isolation and startup gate

Only release AndroidTest receives private Kotlin/tracing runtime copies through the ALL-scoped CLASSES transform. The unfiltered compile classpath supplies complete resolved runtime classes that AGP otherwise subtracts from test runtime inputs. No product keep rules, production debug flags or permissions are added. The standalone ABI regression, actual test APK DEX inventory and unchanged canonical product hash precede startup diagnostics on both APIs.

The startup scope has distinct job/artifact names and sets diagnostic_only true and candidate_qualified false. It cannot satisfy the five-case campaign or accepted release publisher. Full qualification still requires delivery, authoring, process recovery seed/verify and visible Back/About, exact captures and every retained attempt.

The startup diagnostic also exercises the same visible Preferences dismissal, retained draft, installed About fields and offline notices verifier used by the full Back/About case. Full jobs run this preflight first against the same canonical build and retain it separately as startup-diagnostic.json. The two full release-runtime.json summaries remain the only accepted complete API summaries. The emulator explicitly records hardware-keyboard visibility and its default IME; input checks still observe the actual served editor/window before typing.
