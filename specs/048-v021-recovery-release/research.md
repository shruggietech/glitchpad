## D013: Isolate the release test runtime from optimized app ABIs

Observed in run 42489999123: both required API images installed the exact canonical nondebuggable APK and matching-signature AndroidTest, then instrumentation crashed before any journey. R8 mapped Kotlin Intrinsics to F1.e and changed checkNotNullParameter from (Object, String) to residual signature (String, Object); the external test still called the old signature. Trace was also absent after shared dependency subtraction. The failed app/test hashes, mappings, install logs, both attempts and logcat are retained. This failure is test-runtime evidence, not a failed user journey or a release pass.

Decision: add a release-AndroidTest-only ALL-scoped CLASSES transform. Rewrite test callers and seed complete Kotlin stdlib/tracing copies from the unfiltered test compile classpath into private test namespaces. Those classes are appended directly into the transformed test JAR before app mapping is applied. Product artifacts, minification, keep rules, debug state and permissions are unchanged. A standalone JVM regression executes the relocated ABI with only platform classes in its parent loader. A distinctly named startup diagnostic on API24/API36 must pass before the full five-case release campaign.

The Android Gradle plugin applies the app mapping to application AndroidTest with test optimization/minification disabled; the library-only androidTest.enableMinification setting cannot repair changed app signatures. Moving testBuildType earlier alone is insufficient. AGP subtracts tested-app duplicates from runtime collections while preserving compile collections, and its test shrinker consumes the final ALL-scoped transformed JAR.

Primary sources: [AGP variant dependency filtering](https://android.googlesource.com/platform/tools/base/+/refs/tags/studio-2025.1.2/build-system/gradle-core/src/main/java/com/android/build/gradle/internal/dependency/VariantDependencies.kt), [AGP test mapping and scoped-transform handling](https://android.googlesource.com/platform/tools/base/+/refs/tags/studio-2025.1.2/build-system/gradle-core/src/main/java/com/android/build/gradle/internal/tasks/ProguardConfigurableTask.kt), [ScopedArtifactsOperation](https://developer.android.com/reference/tools/gradle-api/8.11/com/android/build/api/variant/ScopedArtifactsOperation), and [AOSP shared-library isolation guidance](https://source.android.com/docs/core/perf/r8-optimization#step-2-migrate-test-driven-keep-rules).

The first isolated startup diagnostic (run 42493807092) launched the actual app and matched its native/frontend source on both APIs, then failed in the test-only WebViewCompat provider observer because product R8 had removed that otherwise unused method. The release observer now reads the already loaded provider through WebView.getCurrentWebViewPackage on API26+, and the Android 7 framework WebViewFactory.getLoadedPackageInfo method on API24. It cross-checks PackageManager version/code and fails if loaded facts are absent. Debug observation remains unchanged. Android 7 does not implement the later dumpsys webviewupdate current-package format, so no guessed dump parser is used. Primary sources: [Android 7 loaded provider](https://android.googlesource.com/platform/frameworks/base/+/android-7.0.0_r1/core/java/android/webkit/WebViewFactory.java#134), [AndroidX legacy observer](https://android.googlesource.com/platform/frameworks/support/+/refs/heads/androidx-webkit-release/webkit/webkit/src/main/java/androidx/webkit/WebViewCompat.java#417), [framework observer contract](https://developer.android.com/reference/android/webkit/WebView#getCurrentWebViewPackage()).
