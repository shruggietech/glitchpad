# S049 PDF interaction and print contract

## View/navigation/metadata

The existing AppFrame is the sole inset, Back and root-focus owner. PdfSurface uses its document region and product TaskSurface, existing semantic tokens/recipes, keyboard/touch interactions and at least the current48dp-equivalent Android targets. Primary page/Fit controls stay reachable; secondary tools are bounded contextual disclosures. Search/outline/thumbnails/password/print tasks remain dismissible and restore the valid opener/current document. No stock viewer or permanent workspace navigation is embedded.

One controller supplies page/label/zoom/rotation/layout, text selection, ordered cancellable search, bounded lazy thumbnails/outline/destinations and validated links. Internal targets belong to the current document and cannot escape it; external schemes use the existing normalized opener only after explicit user activation. PDF actions/scripts/forms/attachment launch and remote resources never execute. Any represented form facts are read-only.

Metadata flows through existing renderer contributions and typed catalog, retaining host-produced source facts, current owner/external revision checks and explicit unavailable/unsupported/error states. Permission flags do not create an additional product eligibility policy. Rendering survives independent metadata failure.

## Print

Print is an explicit current-document operation with captured source/revision and validated selected/all page ranges. Prepare bounded page PNG snapshots via the same PDF engine. Enforce integer/size/dimension/surface/encoded-data budgets before allocation or native staging; retain truthful limited outcomes and cancellation. Source bytes are unchanged.

Desktop uses a dedicated print projection and real native platform dialog path. It may report only observed request/handoff where the platform cannot establish terminal output. It never labels a callback-only result Printed and never infers cancellation from afterprint. Snapshot ownership survives until the print task/system event legitimately releases it; duplicate requests and stale-owner completion are controlled.

Android uses narrowly typed begin/append/seal/handoff/inspect/cancel operations through the existing private source plugin. Job IDs are opaque; no arbitrary native path is accepted. PNG chunks are bounded, dimensions/length/digests are verified and private cache files are job-owned. The native PrintDocumentAdapter decodes/draws one requested page at a time into PrintedPdfDocument and writes only the OS descriptor. It records layout, write, cancel/failure and adapter finish independently from PrintJob status. Pause for OS UI does not cancel a handed-off job; terminal cleanup removes only owned staging. No native original-PDF reparse is used.

Browser print-layout/synthetic provider tests are supplemental. Supported Windows/macOS/Linux native dialog paths and actual Android layout/write/cancel/handoff receive smoke evidence. Unavailable paths must be demonstrated rather than inferred from the current blanket Android print filter. Physical paper output is not claimed.
