# S049 research decisions

**Date**: 2026-11-08. All decisions follow the approved #77-#80 scope. Three read-only research agents inspected the current repository and primary upstream sources; none ran project tooling or changed source. Technical unknowns are resolved into the decisions below, with runtime claims reserved for actual qualification.

## R1. Engine and version

Decision: pin pdfjs-dist 6.5.438 exactly, using its legacy display/worker builds from one locked package. The inspected release was published 2026-11-01 at source 0a4153349dc473ba950fc17941c5ca7eda43c1de; npm tarball integrity was checked and exact-version npm/GitHub advisory lookups reported no applicable advisory on the research date. This is not a security guarantee. Alternatives: an old engine that already targets Chromium69 would introduce known patch-age risk; a stock viewer conflicts with compact shared UI. [Release](https://github.com/mozilla/pdf.js/releases/tag/v6.5.438), [registry](https://registry.npmjs.org/pdfjs-dist/6.5.438).

## R2. Compatibility before broad UI work

Decision: retain Chrome69 and the current four-platform promises. Upstream legacy targets Chrome125+, so compatibility is an application integration that must be measured. Import the existing pinned core-js 3.50.0 stable APIs before the display and worker entries; retain Vite chrome69 transformation and classic IIFE worker output. Check clone/transfer semantics, emitted regex literals/constructors and unresolved module imports. The current inspected legacy files have no literal v/d regex flags; OXC does not supply missing regex semantics or lower top-level await. The early actual API24 probe is diagnostic, followed by API36, before the complete matrix. [Upstream baseline](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions#which-browsersenvironments-are-supported), [Vite](https://vite.dev/guide/build#browser-compatibility), [OXC limits](https://oxc.rs/docs/guide/usage/transformer/lowering#transformations).

## R3. Real worker and decoder loading

Decision: create a caller-owned local classic worker and pass PDFWorker.create({port}) to getDocument; no fake-worker fallback qualifies. Set disableWorkerRendering:true, enableXfa:false, useWorkerFetch:false, useWasm:false initially and conservative actual canvas/decoder feature options. Version/hash-anchor the single upstream WasmImage dynamic fallback import to a static map of the packaged JBIG2/OpenJPEG JavaScript factories, validating replacement count and emitted import.meta behavior. This is a narrow compatibility adapter, not a forked PDF viewer. No sandbox/scripting manager or annotation editor is imported. isEvalSupported is absent from this v6 API and is not a security control. [Display API](https://github.com/mozilla/pdf.js/blob/v6.5.438/src/display/api.js), [decoder](https://github.com/mozilla/pdf.js/blob/v6.5.438/src/core/wasm_image.js).

## R4. Offline resources and font licensing

Decision: use v6 BinaryDataFactory with fixed cMapUrl/standardFontDataUrl/wasmUrl resource kinds and a bounded compiled manifest of bundled resource bytes. Generate needed CMaps and BSD Foxit Symbol/Dingbats data from locked package inputs, preserving notices and hashes; resource responses never accept arbitrary URLs or paths. Prefer embedding these small resource bytes in generated application modules so existing connect-src restrictions need not be broadened for fetching. Exclude the GPLv2-plus-font-exception Liberation1.07.4 TTFs, QuickJS and unused viewer assets. Ordinary PDF uses useSystemFonts:true, disableFontFace:false and leaves standardFontDataUrl unset: this suppresses both worker standard-font fetching (except the BSD symbol fonts) and CSS Liberation URLs. Embedded fonts remain supported; ordinary unembedded fonts use the engine system/generic fallback. Exact glyph appearance may differ when the file omits its fonts; test readability/selection/alignment on each runtime. XFA remains disabled; no blind OFL font swap or baked-metric regeneration is attempted. With useWorkerFetch:false upstream disables qcms ICC handling; record that rendering limitation explicitly. [Factory](https://github.com/mozilla/pdf.js/blob/v6.5.438/src/display/binary_data_factory.js), [font provenance](https://github.com/mozilla/pdf.js/blob/v6.5.438/external/standard_fonts/README.md), [normal substitution](https://github.com/mozilla/pdf.js/blob/v6.5.438/src/core/evaluator.js#L430-L444), [CSS fallback](https://github.com/mozilla/pdf.js/blob/v6.5.438/src/core/font_substitutions.js#L694-L695).

## R5. Native worker response policy

Decision: create the same configured main WebView once after host state setup, with an on_web_resource_request hook that inserts a restrictive CSP only for the emitted PDF worker asset. Worker connect/scripts/subworkers/eval/native IPC routes are denied; initial compiled classic code and typed messages perform its work. Preserve existing main label, geometry, observers and capability bindings. A worker script response may initially have no CSP header, so insert rather than only amend. Dev-server URLs do not receive the native hook; browser tests use a matching response policy, while actual native jobs establish production behavior. [Pinned Tauri hook](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.6/crates/tauri/src/protocol/tauri.rs#L175-L190), [worker policy](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers#content_security_policy).

## R6. Source handles, ranges and stream-only providers

Decision: recognize %PDF- before current whole-text materializers in desktop and Android gateways. Keep source identity/revision in the parent/native adapter; the PDF worker receives only document-owned bytes/length. Use bounded ranges for seekable sources. Add a PDF-specific native private disk spool for nonseekable Android providers with source-size/quota/revision/cancellation cleanup. Such a source may need its tail/index before rendering; report bounded spool progress instead of promising first-page content before required bytes arrive. Do not retain an entire large source in JavaScript memory. Existing picker _/_ can acquire a PDF without changing stable associations/intents.

## R7. Lifecycle and actual resource disposal

Decision: one document controller owns loading task/document/worker, bounded range requests, current render/text/search/thumbnail work, surfaces and print staging. Capture owner/revision on every request, cancel/terminate obsolete work and clear canvases before releasing resource-ledger entries. ResourceOwner.suspend clears accounting only and is not disposal evidence. Preserve the existing 250ms cancellation hard limit, source/page/surface budgets, bounded concurrency and active-tab priority.

## R8. Compact viewer and navigation

Decision: PdfSurface uses the existing AppFrame, TaskSurface, Button/IconButton, Field, Toolbar and ListRow vocabulary. Virtualized visible/adjacent pages, selectable text, page/fit/zoom/rotation/layout controls, dismissible search/outline/thumbnails and validated destinations share one controller and current-session command provider. Keep stronger existing Android 48dp-equivalent targets. Bound extracted text, search results, labels, outline depth/count, metadata and thumbnail queues; report limiting states rather than silently truncating claimed complete results. No new inset/Back/focus owner or permanent workspace navigation.

## R9. Metadata and links

Decision: extend the existing typed renderer metadata contribution/catalog and Document details; host source facts stay host-produced. Parse PDF dates/facts with explicit missing/unsupported/error states and bounded strings. Reuse the current validated external opener only after explicit activation. No PDF script, form submission, attachment launch or automatic action is executed. Permission flags are informative metadata, not new product eligibility or usage rules.

## R10. Truthful cross-platform print

Decision: prepare selected/all PDF pages as bounded raster snapshots through the same PDF renderer, source/revision capture and budget. Desktop native Wry print paths report a system-dialog request/handoff, never physical completion or inferred cancellation. Existing Markdown calls window.print then immediate true; do not copy that as PDF completion evidence. On Android Wry print is a no-op, so add a narrow custom PrintManager/PrintDocumentAdapter using job-owned staged PNGs and PrintedPdfDocument, decoding/drawing one OS-requested page at a time. Transfer bounded chunks to private cache, seal/hash pages, enforce dimensions/encoded/decoded/page budgets and one pending job; clean partial/terminal state. Stage before opening OS UI, and do not cancel simply on activity pause. Record layout/write/cancel/failure/finish separately; finish is adapter completion, not paper output. Avoid a second native parser of untrusted original PDFs and support decrypted PDF.js output. Print work exceeding actual resource budgets reports a concrete limited outcome and smaller-range remedy. [Wry Windows](https://github.com/tauri-apps/wry/blob/wry-v0.55.1/src/webview2/mod.rs#L1712-L1716), [Wry Android](https://github.com/tauri-apps/wry/blob/wry-v0.55.1/src/android/mod.rs#L344-L346), [Android custom printing](https://developer.android.com/training/printing/custom-docs), [HTML printing limitations](https://developer.android.com/training/printing/html-docs).

Only after that preflight run complete keyboard/touch/geometry/native PDF journeys and representative Windows/macOS/Linux packaged WebView proof. Browser and simulated/native cases retain separate classifications. Native print handoff and Android spool paths receive actual smoke. ## R12. Published identity, governance and review boundary

## R13 (2026-11-08): Reuse the existing Rust provider-stream bridge for private spooling

Implementation inspection confirmed AndroidSourceHost already owns bounded native stream leases and revision revalidation. Keep the new private disk cache in a small Rust host module using that bridge, instead of adding a second Kotlin source-cache service and bridge-model family. One active256MiB cache gives a concrete aggregate quota; each advance reads at most256KiB, publishes progress, and is independently cancellable through the real native descriptor. The cache remains source/revision-owned, private and disposable, with partial/close/startup cleanup. This reduces bridge duplication without changing product behavior or the included source criteria. The Android PrintDocumentAdapter still requires Kotlin and remains planned.

## R14 (2026-11-08): Normalize the real PDF port transfer-list default

Actual Chromium69 run42524061027 identified the post-startup failure precisely: PDF.js sent GetDocRequest with an explicit null transfer list, and the native Worker.postMessage binding rejected null as a sequence. The worker had already reported6.5.438 and no native bridge, and the source adapter had read only4096bytes. Normalize null/undefined transfer lists to an empty array on the actual owned Worker instance and PDF worker global port. Preserve the original native receiver, explicit transfer lists/options, messages and real worker identity; no fake worker, global main-thread Worker prototype change or security-policy relaxation is introduced. Contract tests verify receiver/payload/transfer preservation; rerun actual old-browser/native observations before claiming compatibility.

## R15 (2026-11-08): Own display-document resources independently of parser termination

Pinned WorkerTransport.destroy clears fonts/filters only after awaiting a Terminate reply. Immediate native worker termination, required for a stalled parser, can leave that reply pending. Use PDF.js public ownerDocument option to track only its FontFaceSet additions, style/SVG nodes, adopted sheets and document listeners, and synchronously remove them during cancellation. Preserve real document native receivers through a narrow proxy; late work attaches only to an inert document or skips font registration after disposal. Call public TextLayer.cleanup after cancellation microtasks settle. This avoids private engine-field access and keeps cleanup independent of an unresponsive parser. Verify actual repeated native/browser resource baselines rather than counting a cleared ledger alone.

## R16. Runtime readiness and continuous-page ownership

The actual continuous-page journey exposed a viewport/status feedback loop and end-of-document scroll clamping. Status now overlays the page viewport, and explicit page destinations retain ownership while programmatic scrolling settles; genuine wheel, pointer, touch and keyboard scrolling still updates the current page. Search/outline/thumbnails/links use dismissible task surfaces with bounded batches. Worker readiness now also requires dynamic-code refusal measured in the normal worker realm: debugger evaluation can bypass CSP for nested Function calls and cannot supply that evidence. Native/browser/source/runtime evidence remains distinct.

## R17. Minimum-worker dynamic-code compatibility

Run42531545454 passed the entire current-browser reading and isolation journey. Its actual Chromium69 worker reported code_evaluation_allowed:true from the normal worker realm despite the response CSP, and the controller correctly refused to parse. Inspection of the pinned display/worker shows no new Function document-code compiler or isEvalSupported path; only fixed compatibility initialization uses the constructor. After engine/compatibility initialization, a PDF-worker-only guard disables global eval/Function, ordinary/async/generator constructor routes and string timers. The normal-realm readiness assertion remains required. This addresses the demonstrated minimum-browser difference without modifying the main application realm, enabling PDF scripts or relaxing CSP. Future parser changes must requalify the exact pinned code and this policy.

## R18. Worker output and independent inspection bounds

Inspected PDF replies and text streams are now bounded inside the pinned worker before structured cloning to the main WebView. The exact reviewed worker hash and one-occurrence anchors cover outline, labels, destinations, metadata, annotations and per-page streamed text, alongside the existing static decoder transform. The adapter preserves ordinary shared references and rejects cycles or excessive output. Independent metadata/outline/labels/permissions/page-dimension requests report their own availability; one failed or limited inspection does not erase unrelated valid facts. Source information remains host-owned, XMP supplies missing document-information values, and stored permissions remain informational.

## R19. Legacy worker resource guard

Current Chromium applies the worker response script/connect/child CSP, but the actual Chromium69 diagnostic demonstrated that CSP alone is not a complete API boundary there. After all pinned engine/static compatibility initialization, lock the PDF worker's fetch/importScripts/Worker/SharedWorker/XMLHttpRequest/WebSocket/EventSource/WebTransport APIs. The parser has no legitimate network or dynamic decoder imports: source bytes and reviewed resources arrive over the owned message port. Keep the response CSP and normal-realm dynamic-code refusal. Run42535897974 independently observed all worker denial routes and no native bridge on both current and69. No global application network API is altered.

## R20. Print transport and generated light theme

Installed API24 run42536058242 showed native print begin/cancel without a staged page. The PNG transport used Blob.arrayBuffer, unavailable on the minimum Chrome69 profile. Use cancellable FileReader for bounded PNG blobs rather than relaxing the minimum runtime. New actual keyboard/touch/Axe checks also found that the app's selected light theme did not enable the delivered kit's bb-light scope, leaving dark generated fields with inherited dark text. Synchronize that class with the effective selected/system theme, including legacy MediaQueryList listeners. Do not substitute palette values or change the pinned generated kit.

## R21. Validate print page geometry at raster precision

The native raster store must account for ceil-rounded pixel dimensions at the chosen scale. A fixed absolute aspect-ratio tolerance rejects legitimate thin or small page snapshots. Validate that the pixel width and height have a common scale interval for their source-point dimensions instead. Native store qualification includes noninteger point dimensions whose valid ceil-rounded raster has a visibly different ratio. This preserves the dimension binding without an arbitrary page-shape restriction.

## R22. Explicit desktop acquisition and release association inventory

All three delivered desktop candidates timed out before PDF readiness in run42537434321. Inspection found the native delivery queue rejecting .pdf because its acquisition gate reused the released association extension inventory. S049 explicitly requires an acquired local PDF to reach the renderer. Permit manually supplied PDF paths through the established native source acquisition and add the PDF picker filter; content detection still decides the renderer. Keep the released association inventory, packaging registrations and public stable-format records unchanged for #81/#82. This separates existing registration policy from the authorized unreleased reading capability without narrowing any included native criterion.
